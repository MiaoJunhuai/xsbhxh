# 重构计划：登录状态统一管理

> 写给以后负责重构的人（或 AI）。
> 写于 2026-11-26，对应版本：贡品 v1.6.17 / 账号 v1.2.10。
> **已完成（2026-11-26，贡品 v1.6.18 / 账号 v1.2.11）**：判断逻辑已收进 `assets/auth-state.js`，导航栏渲染在 `assets/nav-auth.js`。下面保留计划原文，供以后回溯。

## 一、为什么要做

站点有 8 个 HTML 页面，每个页面都要显示「当前是否登录」。这套判断逻辑**散落在三处、重复了 8 份**，导致同一个 bug 要修三次才修干净。

### 已经踩过的坑

2026-11-26 下午，玩家反馈「登录过期了，页面还显示已登录」。修复过程：

1. 先修贡品页的账号栏 → 玩家说账号页还是显示已登录
2. 再修账号页 → 玩家说导航栏图标还是亮的
3. 最后把 8 个页面的导航栏脚本全部改一遍

**根因**：判断「是否已登录」的代码有三套，各自只看 `localStorage` 里有没有邮箱，不看令牌是否过期。

### 当前的判断依据（错误）

```js
if (localStorage.getItem('xsbhxh_email')) { 显示「已登录」 }
```

邮箱是登录时写进本地的，**令牌过期后它还在**，所以会误判。

### 正确的判断依据

`localStorage['xsbhxh_token']` 是 JWT，解析出 payload 里的 `exp`（过期时间，秒级），和 `Date.now()` 比较。

## 二、现状盘点

### 三处判断逻辑

| 位置 | 文件 | 函数 | 显示的 UI |
|---|---|---|---|
| 全站导航栏 | 8 个 HTML 各一份内联脚本 | 匿名 IIFE | 图标点亮 + 文字「已登录」 |
| 贡品页账号栏 | `tools/tribute-puzzle.html` | `renderAuthBar()` | 「已登录：昵称」/「未登录」/「登录已过期」 |
| 账号页 | `account/index.html` | `render()` | 整个页面在「访客视图」和「用户视图」间切换 |

### 8 份导航栏脚本的分布

| 页面 | 导航栏脚本 | 说明 |
|---|---|---|
| `index.html` | ✅ 有 | |
| `apply/index.html` | ✅ 有 | |
| `rules/one-dragon.html` | ✅ 有 | |
| `rules/tayza.html` | ✅ 有 | |
| `tools/leader-checklist.html` | ✅ 有 | |
| `tools/price-formatter.html` | ✅ 有 | |

每份脚本内容几乎一样（约 25 行），改一次要改 6 个文件。

### 三处各自还有一份 `tokenAlive` / 令牌解析

- 贡品页：`tokenAlive()`、`authState()`、`tryRefreshAuth()`、`uidFromToken()`
- 账号页：`tokenAlive()`、`tryRefreshAuth()`
- 导航栏脚本：内联的 JWT 解析（写在 IIFE 里）

**同一段 JWT 解析逻辑，写了至少 3 遍。**

## 三、目标

1. **判断逻辑只写一份**：`tokenAlive()` / `authState()` / `tryRefreshAuth()` 放在一个公共 JS 文件里
2. **导航栏渲染只写一份**：所有页面引用同一个函数，而不是各抄一段
3. **三处 UI 各自保留**（它们长得不一样，不该强行统一）
4. 以后令牌逻辑再变（比如换存储方式、加新的登录方式），**只改一个文件**

## 四、方案

### 新建 `assets/auth-state.js`

只放「状态和判断」，**不碰任何页面的 DOM**：

```js
// assets/auth-state.js
window.XSB_AUTH = (function () {
  var K_TOKEN = 'xsbhxh_token';
  var K_REFRESH = 'xsbhxh_refresh';
  var K_EMAIL = 'xsbhxh_email';
  var K_UID = 'xsbhxh_uid';
  var LB_URL = 'https://xjyovpninpfztldqoddj.supabase.co';
  var LB_KEY = 'sb_publishable_uDRHXpUMaX9Wa2WJrqefrA_cK27Qqxl';

  function get(k) { try { return localStorage.getItem(k) || ''; } catch (e) { return ''; } }
  function token() { return get(K_TOKEN); }
  function email() { return get(K_EMAIL); }
  function refreshToken() { return get(K_REFRESH); }

  // 解析 JWT 的 exp，返回是否还有效
  function tokenAlive() { ... }

  // 'off' | 'on' | 'expired'
  function state() {
    if (!email()) return 'off';
    return tokenAlive() ? 'on' : 'expired';
  }

  // 用 refresh_token 续期，返回 Promise<boolean>
  function refresh() { ... }

  // 从 access_token 解出 user id
  function uid() { ... }

  return {
    token: token, email: email, uid: uid,
    tokenAlive: tokenAlive, state: state,
    refresh: refresh,
    K_TOKEN: K_TOKEN, K_REFRESH: K_REFRESH, K_EMAIL: K_EMAIL, K_UID: K_UID
  };
})();
```

### 新建 `assets/nav-auth.js`

只负责导航栏那一个图标：

```js
// assets/nav-auth.js
(function () {
  var A = window.XSB_AUTH;
  if (!A) return;
  function paint() {
    var a = document.querySelector('.xsb-auth, .nav-auth');
    if (!a) return;
    var t = a.querySelector('.xsb-auth-txt, .nav-auth-txt');
    var on = A.state() === 'on';
    if (t) t.textContent = on ? '已登录' : '登录';
    a.classList.toggle('is-on', on);
  }
  paint();
  // 令牌过期时先试一次静默续期，成功了再重画
  if (A.state() === 'expired') {
    A.refresh().then(function (ok) { if (ok) paint(); }).catch(function () {});
  }
})();
```

### 各页面改动

**6 个普通页面**：删掉内联的导航栏 IIFE，换成两个 `<script src>`：

```html
<script src="../assets/auth-state.js"></script>
<script src="../assets/nav-auth.js"></script>
```

（首页在根目录，路径是 `assets/...`；子目录页面用 `../assets/...`）

**贡品页**：删掉自己那份 `tokenAlive` / `authState` / `tryRefreshAuth` / `uidFromToken`，改成用 `XSB_AUTH`：

```js
function renderAuthBar() {
  var st = XSB_AUTH.state();  // 'off' | 'on' | 'expired'
  // ...原来三段 UI 逻辑不变，只是 state 的来源换了
}
```

**账号页**：同上，`tokenAlive()` → `XSB_AUTH.tokenAlive()`，`tryRefreshAuth()` → `XSB_AUTH.refresh()`。

## 五、动手顺序

1. 先建 `assets/auth-state.js`，把 JWT 解析、状态判断、续期这三块搬进去
2. 先只改**一个页面**（建议 `tools/price-formatter.html`，最简单）验证能跑
3. 改剩下 5 个普通页面
4. 改贡品页（这个最复杂，`renderAuthBar` 要接三种状态）
5. 改账号页
6. 全站回归测试（见验收）

## 六、验收标准

用**过期令牌**逐页检查（这是最容易翻车的情况）：

```js
// 浏览器控制台
localStorage.setItem('xsbhxh_token', 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJleHAiOjE3MDAwMDAwMDB9.sig');
localStorage.setItem('xsbhxh_email', 'test@example.com');
location.reload();
```

| 检查项 | 期望 |
|---|---|
| 8 个页面的导航栏文字 | 全部是「登录」，**没有一个是**「已登录」 |
| 8 个页面的导航图标 | 全部不点亮 |
| 贡品页账号栏 | 显示「登录已过期 · …」，登录按钮可见 |
| 账号页 | 显示登录表单 + 「登录已过期，请重新登录」 |
| 再检查：有效令牌 | 全部显示「已登录」并点亮 |

**还要测**：把 `localStorage` 全清空 → 全部显示未登录，不报错。

## 七、注意事项

1. **不要改数据库**。这个重构纯前端，`profiles` / `runs` / `scores` 一个字都别动。
2. **`assets/` 已经在仓库里**，新增 JS 文件直接放进去，不需要构建步骤。
3. **页面是纯静态的**，`<script src>` 用相对路径，注意子目录（`tools/`、`rules/`、`apply/`）要用 `../assets/`。
4. **`renderAuthBar` 里还有别的逻辑**（比如控制「登录 / 注册」按钮和「退出」按钮的显隐），重构时别丢了。
5. **改完记得升版本号**并同步 README 的站点结构表。提交说明按 README 的规范写，带板块前缀，例如：
   ```
   导航 · 抽出 auth-state.js，统一登录状态判断
   账号 v1.2.11 · 接入公共登录状态模块
   ```
6. **动手前先 `git pull`**（README 里也写了这条，是两个会话撞车的教训）。

## 八、这个重构能防住什么

- 以后登录逻辑变了（比如加 token 自动刷新定时器、换存储 key），只改 `auth-state.js` 一个文件
- 新加页面时，只要引两个 `<script>`，不用再抄一段判断逻辑
- 「显示已登录但实际提交成游客」这类不一致，从结构上不会再出现
